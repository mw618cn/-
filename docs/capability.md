# 24 h 条件接口域、投影与分解：程序说明

`src/tdm_restore/capability.py` 负责把高维求解结果转成可以解释、可以再分解的接口轨迹。默认连续调度步长为 15 min，内部始终有 96 个时段。图上选择启动时段、中午、晚间三个截面，只是减少画面拥挤，不是将模型压缩为三个时段。

## 1. 计算对象及边界

记当前抢修策略为 π，主模型求出的启动、开关和电池充放电模式为 z̄。所有连续变量组成 x，包含四个场景的 24 h 资源出力、SOC、负荷恢复、接口交换和电压。在固定 z̄ 后：

```math
\mathcal{F}(\pi,\bar z)=\{x\mid A(\pi,\bar z)x\le b(\pi,\bar z),\quad
 E(\pi)x=f,\quad \underline x\le x\le\overline x\}.
```

其中 E 包括相同观测历史下的条件非预期性等式；SOC 递推、末端储能、各时段线路和逆变器能力均继续保留。该集合是一个**固定离散方案下的连续凸可行集**。

接口定义为主模型中两条 T1→D0 通道功率的负和，即正数表示配网向主网提供净支撑：

```math
P^{\uparrow}_{s,t}=-P^{L0}_{s,t}-P^{B}_{s,t},\qquad
Q^{\uparrow}_{s,t}=-Q^{L0}_{s,t}-Q^{B}_{s,t}.
```

本模块投影的是包含上层负荷、主网条件和网络约束的**系统条件接口域**，不能称为独立于主网状态的纯微网固有能力域。它也不包含其他整数启动/开关模式。若研究需要该并集，应枚举更多离散方案，并分别保存条件域，不能把其凸包无条件当成物理可行集。

## 2. 程序各部分做什么

| 函数 | 输入与操作 | 输出及作用 |
|---|---|---|
| `interface_trajectories` | 主模型及高维解；按线路方向取负和 | 全场景、全时段的向上 P/Q 轨迹；避免把本地发电误当接口净输出 |
| `feasibility_residuals` | 将 x 代回 `A @ x`、变量上下界 | 最大线性行/边界/整数违反量；检查见证是否满足数值容差 |
| `_extract_witness` | 从变量索引读出完整高维解 | P/Q、各微网净输出、充放电、SOC 能量、DG/PV、原物理成本 |
| `_projection_steps` | 当前实际启动时间及可配置展示时刻 | 待投影的时段索引；不删去其他时段约束 |
| `compute_capability` | 固定离散方案，逐方向求 LP | 各二维截面的支持点、内凸包、支持半空间、24 h 可行见证及分解证书 |
| `decompose_trajectory` | 所有场景完整 P/Q 轨迹 | 固定轨迹后按原成本解 LP，得到可行的资源指令和跟踪误差 |

函数内按物理关系逐块注释。`solve_lp` 的目标向量仅改变当前要最大化的接口方向，不删除约束。每个方向的解均保存全时域变量见证；相同二维点可以对应不同的资源分解和运行成本。

## 3. 投影为什么需要高维见证

指定场景 s、时刻 t 以及方向 dₖ=(cosθₖ,sinθₖ)，支持函数计算为：

```math
h_{s,t}(d_k)=\max_{x\in\mathcal F(\pi,\bar z)}
\{d_{k,1}P^{\uparrow}_{s,t}+d_{k,2}Q^{\uparrow}_{s,t}\}.
```

`solve_lp` 是最小化接口，因此程序将方向目标取负。每次求解都包含其余 95 个时段和其他场景；这些时段/场景会限制当前接口点。例如，在凌晨大量放电，可能因晚间关键负荷与末端储能约束而不可行。

由成功取得的可行点 vₖ 构成的凸包，是当前条件域的安全内近似；由已证明最优的支持函数得到的半空间交集，则是外近似：

```math
\operatorname{conv}\{v_k\}\subseteq\operatorname{Proj}_{P,Q}\mathcal F(\pi,\bar z)
\subseteq\bigcap_k\{v\mid d_k^\top v\le h_{s,t}(d_k)\}.
```

前一个包含关系利用了“离散方案已固定且剩余模型为线性凸集”的条件。有限方向的内凸包一般不等于真实边界。LP 若只有可行解而未证最优，该点仍可进入内近似，其目标值则不能作为可靠外半空间；代码已区分两者。

默认每个截面 8 个方向；增加方向可改善显示精度，也会增加 LP 次数。若点全部共线或重合，程序不画有面积的凸包，避免制造虚假区域。

## 4. 为什么还要解完整轨迹分解 LP

某一时刻 P/Q 可行，不意味着从每个时刻的图上各选一个点后拼成的曲线可行。SOC 跨期递推和场景间的条件非预期性会把这些选择连接起来。程序因此对一整条候选接口轨迹 \bar u 计算：

```math
V(\bar u;\pi,\bar z)=\min_{x\in\mathcal F(\pi,\bar z)} c^\top x+c_0,
\quad P^{\uparrow}_{s,t}=\bar P_{s,t},\quad Q^{\uparrow}_{s,t}=\bar Q_{s,t},\quad\forall s,t.
```

若可行，返回各微网完整 24 h 的充放电、DG/PV 出力、净交换和 SOC，并报告 P/Q 最大跟踪误差及原约束违反量；若不可行，直接返回失败状态，不以近似追踪代替可行分解。当前默认对原 MILP 轨迹以及一个支持方向的整条轨迹各做一次分解。

该分解是**集中式 LP 的可行性证书**。当前代码没有把它包装成“三级 ADMM 已求解全部整数恢复问题”。若后续实现分布式算法，应在固定离散方案的凸子问题上协调边界功率，并与这里的 LP 目标值、原始残差、对偶残差及分解可行性比较；整数外层仍需单独处理。

## 5. 调用与替换参数

根运行器在获得 MILP 可行解后可调用：

```python
from tdm_restore.capability import compute_capability

cap = compute_capability(model, solver_result["x"], cfg,
                         outdir="results/demo/capability", directions=8)
```

可在配置中加入：

```json
{
  "capability": {
    "scenario_index": 0,
    "projection_hours": [0, 6, 12, 18, 23.75]
  }
}
```

`scenario_index` 只控制展示哪个场景的二维截面，其余场景约束仍在 LP 中。展示时刻必须落在时域内，程序会映射到最近的调度时段。需要 24 个小时截面时可设置 0～23，但应预计求解次数随“截面数×方向数”增长。

输出 `capability.json` 可直接供出图模块读取；`high_dimensional_witnesses.npz` 保存原高维向量，以便检查和二次分析。JSON 中 `reference_decomposition`、`alternative_decomposition` 保存完整资源指令证书，`slices` 保存显示所需的截面点和半空间。

## 6. 本模块能支持的论文结论

可以说：在给定抢修和离散恢复方案下，计算了考虑完整 24 h SOC、网络和信息约束的接口可行截面；每个展示点具有高维见证，指定完整接口轨迹经 LP 校核可还原为资源指令。

尚不能据此说：找到了全部离散恢复方案的精确 MPAR；二维截面可以任意跨时段拼接；已经解决学习型安全投影或一般混合整数 ADMM 收敛；单凭数值算例已证明相对全部现有方法的学术首创性。静态/逐时域与轨迹域的比较，应以同一资源及末端要求进行额外消融，不能由一张截面图推断。
