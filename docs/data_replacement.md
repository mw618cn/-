# 参数替换与真实算例接入指南

示例数据的作用是把建模—求解—校核—出图链条跑通。下面按“改什么、需要什么数据、改后验证什么”说明替换方法。不要先改图中的数值：图必须由新的优化结果生成。

## 1. 单位、时间与功率方向先统一

| 物理量 | 本代码约定 | 常见替换错误 |
|---|---|---|
| 时间 | 小时，调度步长由分钟换算为小时 | 把维修分钟直接写进小时字段 |
| 有功/无功 | MW/Mvar | 将kW、kWh直接当成MW、MWh |
| 储能能量 | MWh | SOC百分数写成绝对能量 |
| SOC | 0—1无量纲比例 | 80%写成80 |
| 电压 | 标幺值；模型内部使用其平方 | 将0.95当成平方电压下限 |
| 线路潮流 | 按配置边的首端→末端为正 | 把微网上送功率与线路正向潮流混用 |
| 上送功率 | 主配联络线正向潮流和的相反数 | 将发电机出力直接当作主配接口交付量 |
| 情景概率 | 非负、总和为1 | 把概率“权重”未经归一化直接代入 |
| 费用 | 统一货币标度；电量项乘MW×h | MW功率乘电价却漏掉时长 |

24小时、15分钟对应96个调度区间；储能有97个边界状态。维修结束时刻、巡检结束时刻和启动候选时刻应与可执行时间网格一致。改变步长后，不仅要改变数组长度，还要重算持续时间、爬坡和费用的时间尺度。

## 2. 替换网络

现有6节点拓扑用于清楚展示主网—配网—微网连接关系。拓扑中，弱联络线L0与修复后的B线是替代关系，不能同时闭合；A线恢复后接入第三个微网。固定边和可恢复边的物理含义不同。

需要准备：节点类型、各节点负荷、线路首末端、额定视在功率、标幺电阻/电抗、电压范围、变压器基准、故障位置和允许的开关状态。扩展到IEEE33/123节点时，必须同时更新节点/边映射、资源接入位置和稀疏平衡矩阵；不能仅把节点数量参数改成33。现有A/B互斥结构按构造保证径向，通用网络还需明确径向/连通性约束。

数据替换后先做三个检查：零潮流情况下电压约束是否一致；已知单向供电工况的有功/无功符号是否正确；停用线路是否同时满足P=Q=0而非仅取消容量限制。线性近似求得的方案应送入AC潮流复核，必要时加安全裕度后重求解。

## 3. 替换负荷与恢复权重

每个节点至少区分关键和一般负荷。微网受保护的关键负荷必须持续供给，是硬约束；其他负荷按费用允许部分恢复。需要真实的24小时需求曲线、功率因数、负荷级别、能否分割、冷负荷恢复特性，以及恢复后能否再次切除的业务规则。

当前连续负荷恢复量表示可分割负荷聚合。若要描述一整条馈线不可分割的接入，应增加负荷块二进制变量；若要禁止恢复后再次失电，应显式增加单调或最短服务时间约束。单纯把失供电惩罚设高并不能替代这两类物理规则。

可以先用常数关键负荷、日内形状一般负荷替换。确认无启动分支能够满足硬保护负荷后，再增加恢复难度。若不可行，先读约束诊断和设备容量；不要用任意大惩罚掩盖硬负荷无法供应的问题。

## 4. 替换微网设备

对每个微网分别给出可控发电容量及费用、光伏预测、逆变器容量、储能额定能量/充放电功率、初始SOC、SOC上下限、充放电效率、末端备用量和关键负荷。固有自启动/构网能力需作为适用条件说明。

初始储能能量为 `E0 = SOC0 × E_rated`；一次15分钟放电0.4MW对应输出0.1MWh，储能内部减少量还需除以放电效率。末端SOC是恢复期可持续性的约束，删除它会明显改变“现在启动”的价值，必须在所有对照组保持一致。

当前充放电模式可采用比连续功率更粗的控制网格，以减少整数变量；如果实际设备允许每15分钟切换，可将模式网格同步调细，并比较求解时间和目标值变化。模式粗化产生的是一个更受限制的可行策略集。

## 5. 替换被启动机组

至少需要：辅助功率分段曲线、各阶段持续时间、启动开始允许时窗、最小/最大在线出力、爬坡率、无功能力和启动费用。若真实机组要求连续启动支撑，必须使用连续时间段或足够细的离散轮廓；不能只输入一个启动总能量。

现有模型允许一次完整启动，不包含失败后中止、冷/温/热态转换与重复启动。若实际启动分阶段可中止，应补充阶段状态机和状态转移规则。参数录入后，先画需求曲线并核算总辅助电量，再验证网络在最不利情景下是否能把功率送达机组端。

## 6. 替换巡检、抢修与情景

现有4情景来自A/B各两种隐含损伤。可用历史灾害、现场评估或专家先验替换概率与维修时长。应记录“何时知道损伤”的观测机制，不只记录“什么时候修好”。

队伍需要：出发位置、位置间旅行时间、巡检耗时、损伤条件下维修耗时、不可中断任务规则和工时限制。本版本是一支队伍执行8种因果策略；新增道路封闭、队伍数量、物资携带或维修前置任务时，需要扩展策略生成或建立显式路由决策模型。

若把维修过程进一步建成随机服务过程，应说明它新增的可观察信息和状态。排队/马尔可夫方法适合多任务等待与服务状态演化，不应仅为了跨学科名词替换已有分段维修时长。用服务时间分布产生情景时，需要保留因果观测与非预见性，避免从“实际修得很快”提前推知尚未检查的损伤。

“极端/恶劣/常规”可以作为情景分组标签，但代表概率、条件维修时间和可再生时序需有清晰来源。简单三场景不自动提供机会约束或分布鲁棒的置信保证。

## 7. 替换初始主网状态

初始外部电源比例alpha控制上级可用支撑；alpha=0表示该初始外部电源不可用，目标机组仍存在且可被恢复。alpha的物理意义应固定，不能一处定义为可用比例、一处又称损伤比例。若使用“退化程度rho”，明确与alpha之间的关系，例如 `rho = 1 − alpha`，并按同一方向解释扫描横轴。

全黑是连续初始可用程度扫描的边界情景。不能先假设D关于alpha单调，也不能预设只有一个临界点；扫描后可能全为正、全为负、不可行区域、多个切换区间或由于求解上下界不足而不能判定。

## 8. 真实数据替换后的推荐顺序

1. 只换负荷、光伏和设备参数，固定一条队伍策略，确认完整24小时可行且校核通过。
2. 接入实际A/B故障、维修时间与旅行时间，查看四情景任务甘特图和观测时间。
3. 放开有限策略选择，记录策略最优值的上下界与计算时间。
4. 求当前启动/等待两个条件分支，用相同终端SOC、费用及信息规则比较。
5. 固定所选离散方案，计算接口域、完整轨迹与微网内部可行分解。
6. 扩充情景数、时间网格或网络规模，报告计算代价和近似误差，避免一次性改变所有因素。
7. 用独立AC潮流、设备动态模型或现场规则检验最有代表性的启动与恢复方案。

每次实验保留解析后的配置、原始求解状态、上下界、校核报告和结果CSV，便于解释“图为什么变化”。

## 9. 直接接入96点真实曲线：不用改优化模型

`config.build_profiles`支持配置的 `profiles`数组覆盖。可以继续使用默认曲线，仅改设备容量；也可以替换全部或部分真实时序。

| profiles字段 | 数组形状 | 单位 |
|---|---|---|
| `pv_mw` | 3×96，行顺序MG1/MG2/MG3 | MW，预测可用PV，不是优化后实际使用量 |
| `load_critical_mw` | 6×96，行顺序T0/T1/D0/M1/M2/M3 | MW |
| `load_general_mw` | 6×96，同上 | MW |
| `grid_price` | 96 | 千元/MWh |
| `critical_voll` | 96 | 千元/MWh，关键负荷损失系数 |
| `general_voll` | 96 | 千元/MWh，一般负荷损失系数 |

改变时间步长时，表中的96随 `n_steps`变化；设备/节点行数当前仍固定3/6。所有数组必须形状正确、有限、非负。覆盖是在默认曲线生成后按字段替换，未提供字段继续使用默认。例如只覆盖PV时，负荷和价格仍按默认规则生成。

### 9.1 用CSV模板导入

`configs/profile_template_96.csv`含默认示例的96行数据，可用Excel打开后替换数值，保存为UTF-8 CSV。表头含义如下。

- `time_hour`：区间起点，0、0.25、0.5、…、23.75；不要添加24.0这一末端状态行。
- `pv_MG1,pv_MG2,pv_MG3`：三个微网预测PV，MW。
- `critical_T0,critical_T1,critical_D0,critical_M1,critical_M2,critical_M3`：六节点关键负荷，MW。
- `general_T0,general_T1,general_D0,general_M1,general_M2,general_M3`：六节点一般负荷，MW。
- `grid_price`：可选电价；模板已给出。还可增加 `critical_voll`和`general_voll`列，单位千元/MWh。

导入并运行：

```bash
python scripts/import_profiles.py configs/profile_template_96.csv --base-config configs/demo_24h.json --output results/my_profiles_config.json
python scripts/run_demo.py --config results/my_profiles_config.json --output results/my_profiles_study --capability
```

`--base-config`可指向已有设备和情景配置；省略时与内置默认参数合并。导入脚本会导出**完整配置**，因此设备参数、情景和曲线可以一起归档。它只验证数据，不运行优化。时段不按顺序、重复/缺行、空值、NaN/Inf或负功率都会报出具体行列。

### 9.2 直接编辑JSON

例如只替换三微网PV，配置中增加 `profiles.pv_mw`，每个微网填写完整96个数。下面的辅助脚本生成完整96点占位JSON；实际使用时将零数组替成真实预测。

```python
import json
n_steps = 96  # 24小时×4时段/小时
patch = {"profiles": {"pv_mw": [[0.0] * n_steps for _ in range(3)]}}
with open("pv_profiles_patch.json", "w", encoding="utf-8") as f:
    json.dump(patch, f, ensure_ascii=False, indent=2)
```

CSV导入方式可以避免手工维护很长的JSON数组。微网能量状态仍由模型求解，不能把希望得到的SOC曲线当作PV或负荷输入。
