# 台风动态故障33节点版：保持原来的三个创新点

**只运行main.py，只维护一份参数数据.xlsx。** 台风模型是场景输入，不作为第四个创新点。

本版仍围绕：①启动／等待的决策边界；②多时段可分解支撑能力域；③信息驱动的抢修—重构—启动协同。

完整解压后第一次安装依赖：

```bash
python -m pip install -r requirements.txt
```

以后在PyCharm/VS Code打开main.py点运行，或在本文件夹执行：

```bash
python main.py
```

不用安装本项目为Python包。highspy是HiGHS的Python接口，用于把通过校核的可行计划交给MILP作初始解，不需要商业求解器。缺少highspy时有SciPy兼容路径，但不能热启动，限时内求解效果可能较弱。

## 一、程序按什么顺序运行

```text
参数数据.xlsx
    ↓ data.py：读数据并检查单位/概率/SOC/时间网格
main.py
    ├─ weather.py：移动风场→危险率→实际潜在故障样本
    ├─ analysis.py：完整96步实际执行
    │    ├─ 只把当前观测放入state，独立采样可能的未来forecast
    │    ├─ repair_model.py：当前已报告故障的候选作业起点、工时、行程
    │    ├─ power_model.py：R优先MILP→次级成本→物理/信息校核
    │    ├─ 观测/维修/新故障或定期时刻→继承SOC和历史，更新未来
    │    └─ 同一真实风灾下执行策略对照
    ├─ 条件LP：全天能力域＋整轨迹分解
    ├─ 初始D_R网格：每点重新优化启动／等待两分支
    └─ plots.py＋data.py：PNG/SVG/PDF和结果汇总.xlsx
```

## 二、8个Python文件各负责什么

| 文件 | 内容和阅读顺序 |
|---|---|
| main.py | 唯一入口，按6步调用其他模块；一般不改 |
| data.py | 行2字段读取→参数检查→96点输入→结果Excel；不存在第二份JSON输入 |
| weather.py | `wind_field`算沿线三点最大风速；`hazard`算每小时危险率；`make_world`生成隐藏的真实首次故障；`forecast`只从当前观测独立预测未来 |
| network.py | 节点/PCC映射、并查集连通分量和环检查；下游重要负荷权重只用于规则基线 |
| repair_model.py | 道路近似行程→安全风速累计工时→当前队伍承诺→任务作业选项；规则基线日程 |
| power_model.py | 稀疏模型工具；①任务与排序，②决定网格，③通用带电森林，④96时段物理模型，⑤条件非预期性；随后是热启动、两阶段求解、解提取与独立校核 |
| analysis.py | `decide`计算D与证据；`simulate`逐步执行；`compute_capability`给条件域与分解；`phase_map`重优化每个网格 |
| plots.py | 只读取实际输入/结果绘图，不求解、不中途补造曲线；估计D与认证分区分开 |

## 三、33节点主配微在哪里

D1—D33为配电网，另加T0/T1主网等值，共35母线、39支路。T0接待启动机组G和剩余外部电源alpha；TX连接T1与D1。MG1/MG2/MG3分别在D18/D25/D33，采用单母线PV+储能+DG聚合。相邻配电线路由DSO管理。

标准33节点32条馈线和5条联络线全部参与台风暴露；主网TS/TX默认不受本地风灾，主网剩余能力由alpha表征。本版默认所有配电支路配置可控开关，这是研究假设，后续可在表格限制switchable。

## 四、故障怎么随时间变化

- 台风路径表给出灾前4h至24h的中心、强度与最大风速半径。采用**简化移动Rankine型涡旋**，不是已标定的完整气象台风模型。
- 对线路两端及中点取最大局地风速，危险率为 `hazard_scale * max(v / wind_threshold - 1, 0) ** exponent`，单位1/h。
- 每条线采样一次指数阈值E。累计危险率积分首次超过E时损坏，故障报告按小时网格对齐。实际电力调度仍是15分钟、24h/96步。
- 灾前历史产生t=0已报告故障；此后还会新增故障。常开联络线同样可能故障，不再固定两条A/B。
- 已故障线路保持损坏，只有队伍实际修完才可用，修复后不会自动合闸。**本版每线路每次台风最多损坏一次，未模拟修后重复受灾。**
- 默认合成样本seed=5产生3处初始故障、全天12处故障。seed可修改，不强制故障数量；单一样本不能代表统计稳健性。

**地理坐标表是单独维护的合成km坐标，不是实测IEEE33位置。** 台风、危险率、道路和工时均为可替换合成研究参数；不声称真实台风验证。道路时间按地理距离×绕行系数/速度上取整，假设道路可通行，未模拟路网阻断。

## 五、抢修优先级与信息怎么处理

只有**已报告故障**进入当前作业集合，未来故障不提前派工。未知轻重时，前瞻作业束为“巡检+重伤维修上界”。MILP选择作业起点、是否安排该任务和一支队伍的先后次序，含行驶时间和安全风速暂停。

实际执行分开：先去巡检；巡检真正完成后才读取隐藏轻重；重新优化是留在当地维修还是去别处。已开始的行程/巡检/维修属于执行承诺，保留剩余工时；天气不安全时暂停并保存进度。

当前预测内，已报告任务的前瞻日程**跨所有预测场景共用**；未知工时取上界，不是完整的内生观测多阶段随机最优/POMDP。未来新故障在下一次真实报告后再入队，预测中的尚未发生故障暂不提前安排维修。因此D证据针对这个有限预测模型，可能保守。

策略选项：

| policy | 抢修规则 |
|---|---|
| joint | MILP联合选择当前故障的作业顺序/起点，功率、开关、启动共同优化 |
| critical_first | 依静态下游关键/一般负荷加权量排序作业；功率和开关仍优化 |
| nearest | 依当前地点的行程排序作业；功率和开关仍优化 |

三策略共用相同真实风灾、资源和观测规则。旧版8条A/B策略不再作为多故障的完整决策空间；原三个创新点定位保持不变。

## 六、开关优化与带电森林

本版不用固定32接线菜单。`closed`为物理开关闭合状态，`energized_bus`为节点带电状态，`energized_edge`为带电闭合支路；物理闭合的无源区域可以仍然失电。

通过虚拟根单商品流、带电边数、可用成网源和电压约束形成径向森林。一个带电分区可有多个资源，但只选择一个虚拟连通根。无源区域允许失电。线路只在当前可用或优化的维修已完成后投入。

主动操作计成本、每线及总次数预算、最小保持时间；预测保护跳闸不计主动操作。真实故障发生首先强制隔离并触发重算，避免把保护跳闸扣掉所有手动预算。

开关按1h前瞻网格决定；真实故障/巡检/维修完成会在当前时刻触发新优化，仍遵守已执行保持时间。未建立详细分合操作序列、同期和频率暂态，假设本地控制完成必要同步。模型可行不等于暂态安全已验证。

## 七、恢复率主目标与D口径

第一阶段最大化24h**加权恢复面积**：关键负荷权重默认5、一般负荷1；微网本地关键负荷仍硬保护。不是仅最大化24h末时刻恢复率。

第二阶段在已找到恢复水平容差内最小化燃料、启机、购电、储能吞吐、抢修队工时和主动开关成本。若第一阶段未证最优，不能把第二阶段称为全局词典序最优。

`D_R = 最大恢复率(当前启动) - 最大恢复率(当前等待)`。等待只禁止当前启动，未来可启动。两分支从完全相同的状态、资源、预测样本和当前信息开始，但可各自优化后续抢修/接线/调度。

预测模型中两分支的R界分别为 `[Ls,Us]`、`[Lw,Uw]`，则D_R界为 `[Ls-Uw,Us-Lw]`。

- 全为正/负：支持启动/等待。
- 整个区间在声明的近似零容差内：已证恢复近似等效，执行上按已找到次级成本选择；不声称次级成本全局最优。
- 界跨零且不够紧：未判。运行时仍按已找到的可行计划执行，不能停住等待论文最优性证明。
- 只有求解器已证当前预测模型不可行才显示灰区；无候选/超时为未判。

MILP有短限时，程序先构造并校核日程和径向接线LP候选交给HiGHS作初始解，再求解MILP。候选不等于最优；结果记录来源、R界和校核残差。

实际96步执行的恢复面积、EENS和成本，**与预测模型的R最优值/上下界分开统计**。每次重算终点仍为原24h，继承真实SOC、开关保持时间、次数和机组/队伍承诺。

## 八、能力域、分解和ADMM的边界

初始已选计划固定全部离散变量后，LP保留完整96时段、全部预测场景、SOC、网络、队伍决定和条件非预期性；沿多个方向查询主配P/Q接口截面，保存每个点的完整高维见证。默认每小时一个截面，共24个，每截面4方向。整条P/Q轨迹再固定一次，求资源分解及残差。

它是**固定离散方案下的系统条件投影**，不是独立MGO能力域，不允许任意拼接截面点；也不是未知真实未来的安全保证。实际观测会更新未来计划。本版没有实现ADMM，采用集中式HiGHS MILP＋条件LP；ADMM可作为后续固定离散方案后的连续协调求解方法。

## 九、怎样先跑通和怎样做论文仿真

可将`run_coordination_baseline`设为“是”额外运行禁向上反送对照；只添加主配接口禁反送约束，同资源和真实风灾，其他耦合保留。该基线用于评价允许上送的价值，不等同于三层彻底分离。默认关闭。

默认：24h/96步、2个独立预测场景；联合策略与重要负荷策略对照；24个能力截面；3×3初始D_R相图。每个主目标MILP限时5秒，二阶段1秒，相图主目标3秒，另有建模/LP校核时间。

全部流程有多次建模和求解，耗时取决于电脑、故障数和开关设置，可达数分钟至更长。控制台持续打印时刻和进度，不要以单个5秒限时估计总耗时。

想先快速检查，在运行设置改：`run_comparisons=否`、`compute_capability=否`、`compute_phase_map=否`。仍执行完整24h，只减少附加实验。

论文仿真建议逐项增加：

- 提高`solver.primary_seconds`、`solver.secondary_seconds`、`solver.phase_seconds`，观察R上下界收紧；默认短限时结果只用于先跑通。
- 增加预测场景数、不同台风轨迹/强度、多个seed；将其作为独立重复实验，而不是用一次样本宣布普适规律。
- 细化相图网格，保持同一初始故障与预测随机数；相图估计曲面和认证分类分别看。
- 改critical_weight体现不同关键负荷偏好，检查操作预算/保持时间、储能和启动轮廓敏感性。
- 后续真实参数替换时检查地理/气象/脆弱性/道路/工时来源。

## 十、结果在哪里

`results/运行_日期_时间/`包含：

- **结果汇总.xlsx**：实际恢复指标、24h功率、97点SOC、故障/巡检/维修事件、39支路开关/潮流、沿线风速与条件故障概率、滚动D证据、D相图。
- **figures/**：每图PNG/SVG/PDF。图01风灾，00位置与全部开关，02物理故障与开关，03协同功率/SOC，04韧性，05队伍/信息，06滚动D，07全天域与分解，08D曲面+认证相图，09策略比较，10节点拓扑快照。
- **joint/**及对照策略目录：每次滚动预测的分支界、可行性和真实执行记录。
- **capability/**：条件域、整轨迹分解证书、压缩高维见证。
- **phase/**：每个网格两分支实际重优化的数值与分类。
- **本次参数.xlsx**和**运行汇总.json**：避免不同参数/不同随机样本的结果混用。

若意外没有正常可行计划，未完成的机组启动可保守中止，已耗能量不退回；有显式记录的应急保供可把终端目标储备放宽至物理SOC下限。应急结果不当作原正常储备约束证书。默认验证需报告是否触发此项。事件时段允许参数给定的紧急机组降出力，未模拟其暂态。

标准接线、R/X、原Pd/Qd来源：MATPOWER case33bw，Baran & Wu (1989)，DOI10.1109/61.25627。其余参数为合成研究输入。单母线微网、无损线性潮流、内接多边形容量、首次故障、单队伍和有限预测样本等边界均需在论文中声明。

`generator.last_start_hour`沿用旧算例的8h启动窗口；如果研究台风退去和抢通后再启动，可将其改为更晚时刻（例如20h），再重算D。该参数属于模型条件，不能把窗口内的等待结果解释成任意时刻均可启动的结论。

当前合成参数下，seed=12会生成初始入口L01_02和联络TIE3故障，可用来检查无外部电源时“当前启动不可行”的机制；这是一个指定随机样本，不是普适台风结论。本轮已检查其初始D判据，未把它当成第二套完整24h验证结果。
