# r2 修复包：替换后仍只运行 main.py

1. 先备份你现在整个代码文件夹。
2. 将修复包内的 7 个 `.py` 文件全部复制到原来的 `main.py` 所在目录，覆盖同名文件。新增的 `capability.py`、`diagnostics.py` 也必须放在这一层。
3. 本包的 `参数数据.xlsx` 保留上一版物理和台风参数，只把主目标/相图预算改为8秒、投影方向改为8、禁反送对照设为“是”。若你已经修改过参数，请保留自己的Excel，并自行调整上述运行选项。
4. 运行 `main.py`；不要运行旧目录内的入口。输出会创建新的 `results/运行_日期_时间/`，不会覆盖旧结果。

若不确定原目录是哪一版，使用完整 r2 包，解压后直接运行其中的 main.py 更稳妥。依赖与上一版相同。

## 本次具体修复

- 充电、放电候选始终同时计算；另有白天充电的混合候选和释放电池模式的小邻域搜索。全部候选经过完整时域校核，MILP或二阶段不能无记录丢掉更好的已知恢复水平。
- 联合抢修增加就近日程候选，仍由完整MILP选择；规则对照的抢修日程按各自规则固定。不会为拉开曲线而改负荷、故障或恢复率。
- 显式增加 MGO–DSO 的 PCC 有功/无功轨迹变量。由真实SOC和当前预测生成的累计能量包络进入每次全局优化；微网内部状态保留，形成可分解见证。
- 能力域图改成微网局部资源域，完整保留96时段SOC及本地约束，固定充放电模式；网络可送范围另外计算和标注。网络隔离造成主配接口不能送电，不再被误标成微网资源能力消失。
- D曲面只表示当前取得的可行计划差值；求解界跨零时保留“未判”，不根据插值假造临界线。
- 默认增加“禁止向上支撑”对照，用于检验允许主配反送的作用；它不是彻底取消所有三层协同。
- 抢修图区分有效巡检、有效维修、天气等待和行程；不把天气等待全部算作巡检工时。
- 新增求解质量、候选恢复率、策略对照和滚动包络记录。结果退化时直接提示。

## 运行后先看什么

1. `结果汇总.xlsx`：先看“策略对照”“求解质量”“滚动能力包络”“微网资源出力”“质量提醒”。
2. 图03：实际24小时功率与SOC；图07：预测条件资源域、整轨迹分解及网络可送范围；图08：D计划差值与判据；图09：策略实际对照。
3. `结果质量检查.json`：超时比例、求解间隙、储能利用、相同轨迹提醒及已判相图数量。
4. `joint/rounds/`：各轮的 `seed_candidates`、`best_seed_R`、`primary_R_plan`、`R_lower/R_upper`、`interface_envelopes` 可追溯候选、界与输入包络。

## 这次没有宣称完成的部分

- 采用集中式MILP及局部条件LP，尚无ADMM。
- 进入调度的是跨期必要能量包络及保留内部变量的扩展形式；没有把高维非凸域完全投影成独立接口不等式，也不是Neural MPAR。
- 图07是固定模式下的条件资源域，不能任意拼接截面，也不包含所有充放电模式。
- 仍使用有限风灾预测样本、未知工时上界和观测后滚动，不是完整POMDP或全局最优信息获取策略。
- 当前初始预测不预先安排未来未报告故障的维修，所以其网络可送范围可能很保守。图中保留该事实；实际观测报告后会加入维修任务并重算。
- 相图仍可能未判，联合策略也可能与规则相同或在某条实际灾害路径上较差；必须看求解质量和多样本验证，不能预设优势。
