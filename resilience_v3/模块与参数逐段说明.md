# 按“参数 → 状态与场景 → 模型 → 求解 → 执行 → 出图”阅读代码

主程序只需运行main.py。下述按函数而不是代码行号解释，避免后续增加注释造成文档行号失效。每个模块已在职责边界处标注假设；模型行还有名称，可用于定位约束残差。

## 1. 参数层：data.py、network.py

`rows`读取Excel第2行字段、第4行起数据；`number/boolean`拒绝空数值、非有限数及错误布尔文字。`load_parameters`依次组装基础参数、节点/线路/微网映射、台风路径、N时段曲线、启动轮廓和算法设置。`validate_config`检查时间网格、SOC、效率、容量、先验、主配接口和正整数设置。曲线默认为基值×标幺倍率，PV按装机×倍率；不能把MW绝对值直接填进倍率列而再次乘装机。

`network.prepare`生成TX索引、微网节点、邻接关系及R分母；静态修复优先级只用来构造规则候选。重要负荷是关键服务需求及其权重，不是“离主网近的线永远优先”。静态下游权重也不是每个决策时刻真实边际收益。

| Excel工作表 | 主要内容与调整要点 |
|---|---|
| 基础参数 | Δt、H、α、电压、操作预算、机组、队伍、MILP时间；钱的单位按表为千元 |
| 节点负荷 | 节点名、关键/一般负荷基值、无功比、protected标志、示意图坐标 |
| 地理坐标 | 单独的km坐标，用于风场/行程；不拿接线示意坐标冒充GIS |
| 线路参数 | 接线、RX、容量、暴露性、开关、危险率及检修时间；plot_route仅控制示意布线 |
| 微网参数 | PV/DG/电池/逆变器、效率、SOC与成本；可改容量及接入点 |
| 台风路径 | 覆盖灾前历史到H的中心、强度、半径；输入要按时间严格递增 |
| 24小时曲线 | 恰好N行；负荷与PV倍率、价格倍率；换步长/H时须同步重建 |
| 启动曲线 | 相对启动时刻从0按Δt连续排列的MW辅机需求；完整保留峰值与持续时间 |
| 运行设置 | 场景数、域/相图、对照策略、输出路径 |
| 算法与绘图设置 | 类型展开K、候选规则、精化、滚动、后向储备、字体/分辨率等 |
| 数据来源与标定 | 区分标准数据、建模借鉴和待标定合成假设 |

输入不是任意规模自动生成功能：改节点/微网数量要补对应负荷/PV列及接线，地理表也要匹配；仍是一台待启动机组、一支维修队伍和一条命名TX接口的模型。

## 2. 环境与预测层：weather.py

`wind_field`对简化涡旋参数插值，在每条线三个点取风速最大。`hazard`返回1/h危险率，不直接返回整次台风损坏率。`make_world`建立一次实际潜在灾害，含灾前首损、未来首损和隐藏类型；它由仿真环境持有，不交给优化器。

`forecast`只接受当前state，独立随机数产生可能的未来故障，不读取world的未来。当前风速按已观测数值更新；天气场景和类型笛卡尔展开分开。`forecast_scenarios=1`是计算演示，不能据此声称天气不确定性已充分采样。

故障样本的seed相同则便于公平重算，改seed会改变结果；禁止为“好看”把故障强行固定到某两条线。每条线首损后保持损坏，直到真实维修完成；当前无修后重复损坏。

## 3. 任务和信息层：information.py、repair_model.py

`expand_hidden_types`从当前已报告未知类型中选优先级最高的K条，展开2^K light/heavy，并与全部天气路径交叉。其余未知类型采用heavy工时。`policy_names`读取当前比较的规则类，`make_crew_plan`逐样本推进因果规则并输出availability、trace、dispatch、tasks、histories、reveals。

一个时间步的内部顺序是：加入当前已报告故障 → 记录当前信息历史 → 在没有正在执行任务且风速允许时派工 → 记录当前可用线路和作业状态 → 推进Δt行程/作业 → 完工后揭示类型或恢复线路可用性。故障在时段开始可知，检查结果在实际完成的下一时段开始才可用于动作。

规则的预期工时由先验算，不把隐藏类型当作已知；唯一读取预测severity的位置位于“预测检查完成”之后。`validate_policy`独立检查同一信息历史动作一致，以及上一任务结束前不能分派下一任务。旧repair_model自由排序工具是兼容实现，默认R3使用显式因果策略树，不要把保留工具误认为默认自由路径MILP已实现。

实际环境通过analysis.advance_crew在实际检查结束后读取实际类型。默认任务承诺是一整段“出发到检查完”或“出发到维修完”；不是只锁现场工时，也不是把所有未来排程锁住。道路行程为距离×绕行系数/速度，按Δt取整；不是完整道路路网/随机排队模型。

## 4. 能力和后向层：capability.py、reachability.py

`interface_envelopes`产生每微网、每样本的累计PCC电量上下界，覆盖当前一步及若干累计时长/终点，进入全局模型。它的作用是提前筛掉能量不可能的指令；保留内部变量，避免把必要包络当成充要条件。

`build_resource_model`移除TSO/DSO网络，保留固定电池模式下的全部时段、SOC、服务、逆变器、终端储备和NA，得到局部LP。`delta_interval`对4变量LP作等价解析消元求单步能量变化端点（独立测试与原LP对照）；`island_reserve_tube`从终端SOC集合向前驱递推；`certify_commands`再针对选定PCC等指令，在当前信息树上求条件后向管，遇未知子分支先交集。

后向是数值递推顺序向前驱，不是把物理时间倒过来运行。标量区间算法有单母线凸线性假设，文档中列出范围；不直接套在完整混合整数网络上宣称精确消元。

## 5. 全局模型层：power_model.py

`ModelBuilder`把变量编号、上下界、整数性、目标与命名稀疏约束行构成LinearModel。`build_model`按以下块组织：

1. 接入给定候选因果作业树的线路可用性与作业费用；兼容路径可建立自由作业变量。
2. 建立拓扑决定网格、机组启动候选网格、储能模式网格。故障/修复/信息/派工事件加入拓扑网格；功率和SOC仍每Δt建模。
3. 建立开关闭合、带电节点/边、虚拟根和连通流，保证带电森林并计可控操作。
4. 每时段建立负荷供应、源出力、PV/充放电、PCC、SOC、节点PQ、压降和多边形容量。
5. 加入继承状态、启动辅机轮廓/爬坡、累计能量包络、安全后备管和条件非预期性。
6. 保存变量索引、模式/时间映射、原始成本目标、状态及信息树，供求解与独立提取校核。

`safe_seed`用不同充放电计划、可行径向接线和LP构造已校核候选；候选只是热启动，不替代后面的MILP。`solve_mip`优先用highspy接入热启动，缺少时可走SciPy但效果不等同。`optimize`恢复优先、成本次之，始终保留更好的已校核候选和真正求解界；局部模式邻域的界不冒充完整MILP的界。

`extract`由统一索引取数组，不重算或美化结果。`validate`除了稀疏行残差和整数性，还独立重建PQ/SOC、森林/源、任务时序、主动开关和信息一致性。无可行解/整数不足时不能出具成功证书。

## 6. 决策和滚动层：analysis.py、rolling.py

`initial_state`初始化观察到的故障及实际SOC；`decide`为start/wait分别评估有限因果规则，合并类上下界，必要时精化同一问题，用区间判D，并为所选候选计算后向证书。

`simulate`循环N步：观测 → 判断旧信息树/作业进度是否还匹配 → 联合MILP或固定离散的剩余LP → 全面校核 → 执行一步 → 实际队伍推进并观察。不是一次预测直接当作24h运行结果。

`_compatible`同时核对故障报告、检查结果和正在执行任务的剩余进度。如果预测已经得到“轻伤”，实际巡检还没完成，旧树无兼容分支，必须重算，不能偷用未来类型。风速导致进度偏离同理。

`rolling.refresh_continuous`固定真实已执行前缀和当前SOC，对兼容样本重新赋条件权重，只更新剩余连续功率。在两次联合优化间暂时保留离散计划以节省计算；下一事件可以重新选择未开始任务和未来开关。LP不可行时转联合MILP，不硬执行旧功率。

`compute_capability`方向查询完整局部LP → 保存全时域见证 → 固定完整参考PCC做分解 → 保存共同λ轨迹凸包 → 实测逐时拼接是否可行。`phase_map`只在独立复制的初始状态改变α/SOC，使用相同预测随机数重新求start/wait。

## 7. 结果与绘图层

`diagnostics.audit_results`独立重算实际R/EENS、节点PQ和SOC动态；检查故障线未闭合、充放电不同时、N步执行/固定终点、域分解和对照口径。它区分模型可行与最优性未证。`write_workbook`将原始时序、D/界、任务/开关、每步控制器和后向检查写为普通xlsx。

`plot_style.setup/save`先找宋体，检查字体及字形，按列宽导出PNG/PDF/SVG。`plots`只消费结果字段；没有结果/原始证据就不画对应认证图，不补造D轨迹、临界边界、失效概率或信息到达。

## 8. 常用计算精度与性能设置

| 设置 | 作用与代价 |
|---|---|
| forecast_scenarios | 天气路径数；与2^K相乘后才是模型样本总数，扩大后耗时/内存增加 |
| information.max_hidden_targets | K；控制显式未知类型数，其余仍为heavy上界 |
| information.crew_policies / max_policy_candidates | 候选规则及截取数；增大时D界的策略类含义也变了，不能和旧类界混合 |
| solver.primary_seconds / secondary_seconds | 单候选求解时间；仍另外存在候选LP、校核等时间 |
| solver.phase_seconds | 每个相图两分支中使用的主阶段预算，不是整张相图预算 |
| solver.decision_refinement_rounds / seconds | 同一问题追加求解精化；不改样本或策略类 |
| replan_hours / control.full_milp_each_step | 周期联合重算或每步完整联合重算；事件仍可提前触发 |
| generator.start_interval_hours | 未来启动候选网格；当前重算起点始终可比较当前启动 |
| reachability.enforce_island_reserve | 额外岛内关键服务到终点的后备约束；关闭改变策略可行域，须做匹配消融 |
| plots.phase_surface | 额外输出实际采样点/线框，不做平滑插值或伪造曲率 |
| plots.font_file / dpi / width_mm | 原版宋体路径、PNG分辨率和列宽；不影响数值解 |

改变设置后重新运行会生成新结果目录，旧结果不会覆盖。先用默认小场景数检查逻辑，再提高样本/精度；计算规模扩展不等于已经建立了新的方法创新。
