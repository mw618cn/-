# 33节点主配微协同韧性恢复

只运行 **main.py**，所有参数集中在 **参数数据.xlsx**。先把ZIP完整解压，不要只双击压缩包中的main.py。

第一次安装依赖：

```bash
python -m pip install -r requirements.txt
```

以后在PyCharm/VS Code打开main.py点击运行，或在解压目录执行：

```bash
python main.py
```

程序自动读取Excel → 先画参数接线图 → 生成因果巡检/抢修日程 → 建立完整24h随机MILP → 求解/校核/比较D0 → 出图和结果Excel。每次结果存在独立的 `results/运行_日期_时间/`。

## 这一版如何体现主—配—微

| 层级 | 位置 | 控制内容 |
|---|---|---|
| TSO主网等值 | T0、T1两个新增节点 | T0上的待启动机组G及剩余电源α，T1上的主网负荷；通过TX和配电节点1交换P/Q |
| DSO配电网 | D1—D33，共33节点 | 37条标准配电支路（32条原常闭支路、5条原常开联络线），巡检抢修、径向接线、负荷恢复、潮流与电压 |
| MGO微网 | MG1在D18，MG2在D25，MG3在D33 | PV、DG、储能及该母线负荷；完整96时段SOC和终端储备，保护关键负荷 |

**因此总母线数是35，不把两个主网等值节点算进33个配电节点。** 微网是单母线聚合电源与负荷，并未额外建立微网内部多节点网络。相邻配电线路归DSO管理，PCC净交换取所在母线所有相邻线路的有向和。

**五个常开联络开关：** S33=21—8，S34=9—15，S35=12—22，S36=18—33，S37=25—29。

**初始故障：** A=12—13（S12），B=27—28（S27）。位置已知、轻重未知，巡检完成后揭示；修复完成才允许合闸。S02、S03、S06、S09是本版接线菜单采用的健康分段开关，见图和Excel。开关可为径向重构再次打开，修复完成不等于必须立刻合闸。

## 为什么不只在旧表里新增节点

本版已修改节点/支路维度、MG接入映射、主配接口符号、各节点原始Q/P、39支路P/Q约束、电压、开关状态、因果信息绑定、校核、滚动前缀锁定、能力域投影及分解接口。旧6节点版保留在仓库simple_version，避免混用。

## Excel表格怎么用

保留第2行英文字段、第3行中文说明，从第4行起修改数据并保存。用Excel或WPS打开；IDE提示“No loader”仅表示缺少预览插件。

- **节点负荷**：35节点负荷、关键负荷硬保护、各节点Q/P、绘图坐标和角色。D1—D33的原Pd/Qd来自标准算例；以30%/70%拆分关键/一般。
- **微网位置**：三微网接入点；**微网参数**：容量/功率/SOC/成本。
- **线路参数**：39条线的端点、容量、阻抗、初始状态、是否装可操作开关、编号、故障A/B、图中折点。初始状态用于动作前示意；t=0允许选择菜单接线，假设开关瞬时完成。
- **接线方案**：32个显式候选径向森林，每行列出断开线路；其余线路闭合。程序检查无环、固定线不得打开、每个连通分量含成网微网。故障线仅在已修复后才可使用。
- **巡检抢修/行程时间/损伤场景**：保留A/B轻重四场景和同一因果信息规则；不把电气距离当作道路行程。
- **基础参数/启动曲线/24小时曲线**：主网剩余能力、线性网络、启动功率轮廓、完整96个15分钟PV/负荷/价格。
- **运行设置**：开关控制所有附加分析。

修改微网位置、故障位置或接线菜单后，必须确保每个候选分量仍有成网微网；检查失败会明确报错，而不会让没有电源的孤岛凭空供电。

## 首次默认运行和完整研究设置

交付默认：24h/96时段/4场景，抢修策略 **B_11**，32个接线候选，比较当前启动与等待；每个MILP限时90秒。能力域、条件代价面、滚动和禁反送基线默认关闭，以便先检查33节点接线与物理结果。**只选B_11时，D仅代表此抢修策略内的决策；不是完整8策略的结论。** 不同计算机速度不同，无可行候选时会停止，不会用假结果画图。

需要完整研究时，在运行设置中修改：

| 项目 | 设置 | 作用 |
|---|---|---|
| policy_ids | all | 比较完整8种有限因果抢修策略；计算量增加 |
| compute_capability | 是 | 全24h条件能力域和整轨迹分解；每个方向LP仍保留96时段 |
| capability_interval_hours | 1（或0.25） | 24个每小时截面（或96个15分钟截面） |
| compute_cost_surface | 是 | 固定离散方案后的SOC/启动倍率LP条件代价扫描 |
| run_rolling | 是 | 按真实巡检观测进行固定抢修策略滚动 |
| compute_baseline | 是 | 同菜单、同场景禁反送对照 |

能力域与代价面附加分析较多，建议分步开启。33节点版比6节点版明显更慢。提高solver.time_limit可改善候选解与界；D区间跨零只说明目前不能可靠判定。D0仍是初始“等待−启动”的费用差，不是每轮都重新计算的Dτ。

## 数据来源和当前模型边界

标准接线、线阻抗、原始节点有功和无功来源：MATPOWER官方case33bw，Baran & Wu (1989), DOI **10.1109/61.25627**，https://github.com/MATPOWER/matpower/blob/master/data/case33bw.m 。10MVA、12.66kV下Zbase=16.02756Ω；Excel阻抗已从欧姆转换为标幺，电压公式用MW/baseMVA。

标准算例没有给出本文所需的真实电源、抢修道路/时间、天气故障、热额定和主网启动参数。这些数值均为可替换研究假设。不是实测台风验证。保留节点Q/P，而非统一功率因数覆盖原始Q。

求解器仍为**集中式SciPy/HiGHS MILP**，**尚未实现ADMM**。拓扑优化限定在32个显式径向森林中，不遍历所有可能的开关组合；抢修限定在8种因果策略中，不是任意VRP。每个分量预设有成网微网并已完成初始送电；不模拟送电/频率/同步/励磁涌流/保护暂态。网络采用无损线性潮流和视在功率内接多边形。能力域为固定离散方案后的系统条件投影，不是独立微网本地MPAR的分布式协调证明。

请勿把有限菜单范围内的费用界推广成所有拓扑/任意抢修路线的全局最优界，或把固定方案LP不可行推广成所有恢复策略不可行。

限时但没有MILP候选时，程序还会尝试一个**固定离散方案LP可行回退**：保持一个初始可用径向接线、固定电池模式，当前启动分支在0h启动、等待分支在下一允许时刻启动。它保留原模型全部物理及信息约束并接受同一校核，只能给出可行费用上界；原MILP没有有效下界时仍报告无法判定D，不会把受限LP最优值当成原问题最优值。滚动重算继续使用已执行历史下的原计划回退。
